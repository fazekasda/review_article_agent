# 15 — End-to-end evaluation, scale, and local release

## Dependencies

14 and all previous acceptance criteria. This step validates integration; it does not replace missing predecessor tests.

## Deliverables

- Human-reviewed end-to-end demonstration on authorized representative papers, with complete provenance and limitations.
- Synthetic 1,000- and 10,000-candidate operational tests without implying 10,000 paid model calls or copyrighted downloads.
- Fault/recovery suite, installation/upgrade/migration guide, operational guide, troubleshooting and scientific limitations documentation.
- Release checklist and accurate feature/support matrix.

## Acceptance criteria

- Demonstrate brief→seed approval→plan→freeze→acquisition→pilot→screening/audits→extraction/audits→synthesis→outline→blueprints→draft/review→origin tracing→notes/freshness→final approved exports.
- Deliberately inject an unavailable source, false exclusion, omitted finding, unsupported claim, false critic objection, ambiguous citation chain, and post-approval edit; verify required stops and corrections.
- Close CLI, interrupt worker/harness independently, lose events, duplicate admissions, and restore backups on disposable instances. No lost scientific approval or duplicate accepted result; ambiguous external spend remains documented.
- Two stored projects remain isolated and cannot execute concurrently. Safe activation/pause/switch behavior is demonstrated.
- Scale tests report measured elapsed time, memory/storage, queue behavior and failures against budgets agreed in 01; no invented universal latency or cost promises.
- Human pilot/audit observations are labelled calibration/inspected-sample evidence, not held-out accuracy or completeness guarantees.
- Required visual/supplement evidence is actually interpreted or escalated, despite text-only manuscript outputs.
- Package installation and documented recovery work in a clean test environment; secrets are excluded from logs, fixtures and exports.

## Handoff and release authority

The user reviews measured limitations and the complete demonstration before declaring an initial release. No automatic publishing, pushing, service autostart/lingering, cloud deployment, or journal submission. Leave a final handoff with supported runtime versions, all known gaps, and the next explicitly authorized work.
